# MATH-500 2026.10.1

Methodology for the `eval_math_500_2026.10.1_ctx32768` benchmark, defined in
the production catalog. The sampling and
seed rules shared by every eval, repeats included, are in
[`benchmarks.md` §2.5](../benchmarks.md#25-eval-accuracy) § Execution, the
bound on prompt plus output is
[§ The context bound](../benchmarks.md#the-context-bound), and the scoring
contract is [`scoring-service.md`](../scoring-service.md). mgmt loads the entry
and owns the proxy/storage path; scoring runs in `pipette-scores` and
generation in `pipette-clients`.

## What it measures

The same 500 competition problems as [MATH-500 2026.06.1](math_500-2026.06.1.md),
from the same pinned `HuggingFaceH4/MATH-500` revision, with the upstream
`answer` column as gold. The prompt and the grader differ. This version
reproduces the `math500` task of liquid_evals, Liquid's offline eval harness,
whose runs give the MATH-500 number on Liquid's model cards. The dataset build
checks that the gold equals the answer that task grades against, on every row.
2026.06.1 reproduces liquid_evals' other track, `math500_std`, which follows
the Artificial Analysis method.

## How it runs

500 problems, each completed 5 times and served by the scoring service as
`<id>#0 … <id>#4`: 2500 completions per model, one warehouse row each.

The entry pins no temperature, so a client samples at `0.6`, the value
`eval_temperature()` (mgmt's `crates/pipette-plan-types/src/benchmark/mod.rs`)
falls back to for this eval id. No fixed seed is sent, so repeated attempts are
independent draws.

`parameter_max_tokens` and `parameter_max_context` are both `32768`: a sample
stops once its prompt plus its output reaches 32768 tokens, as in liquid_evals'
`math500`. Only a vLLM or llama-server cell can run the entry.

**Prompt.** One user message and no system prompt. Free-form generation: no
constrained decoding. The model receives:

> {problem}
>
> Please reason step by step, and put your final answer within `\boxed{}`.

## Scoring

The dataset names its grader (`metadata.grader = "liquid_evals_math500"`), and
`pipette-scores` runs liquid_evals' `extract_math_answer` and
`verify_math_answer`, copied unchanged, as the `math500` task calls them:

- Reasoning blocks are stripped before scoring.
- The answer is the last `\boxed{}`, read by counting braces so a nested answer
  stays whole; else an answer line (`###`, `ANSWER:`, "the answer is", "final
  answer"); else the last number.
- It is correct on an exact match with the gold, else on equivalence under
  Hendrycks' MATH answer normalization or PRM800K's sympy check (so `1/2`
  matches `0.5`). Failing that, the same check runs on the response if it
  starts with "final answer:", "the final answer is", "answer:" or `###` (with
  that prefix removed), then on each of its last 150 lines.

## Reported metric

mgmt derives `accuracy = correct / total` over the 2500 attempt rows. Because
each attempt is its own row, this **equals pass@1**: the mean correctness over
the 5 attempts. The scorer also emits `math_500_pass_at_1` (plus `_stderr`,
`_per_sample`, `math_500_unparsed_rate`, and a
`math_500_extraction/{boxed,hash,answer_colon,answer_is,other,numeric,none}`
distribution) in the response `context`; mgmt persists `context` opaquely.

## Differences from 2026.06.1

| | 2026.06.1 | 2026.10.1 |
|---|---|---|
| Reproduces | liquid_evals `math500_std` (Artificial Analysis) | liquid_evals `math500` (Liquid's model cards) |
| Prompt | instruction, problem, then a reminder | problem, then instruction |
| Answer extraction | last `\boxed{}`, `\fbox{}` or `\framebox{}` with at most one level of nested braces, else the last number | last `\boxed{}` at any nesting, else an answer line, else the last number |
| Grading | PRM800K's check (Hendrycks' normalization, else sympy), then robust-boxed numeric normalization | exact match, then the same PRM800K check (sympy skipped past 3000 characters or 100 LaTeX macros), then the response's last 150 lines |
| Token limit | the output alone, at `parameter_max_tokens` (8192 in `eval_math_500_2026.06.1`) | prompt plus output, at 32768 |

Both serve the same 500 problems and gold, 5 times each, at temperature 0.6.
Because the prompt, the answer extraction, the grader and the token limit
differ, a 2026.10.1 score is not comparable with a 2026.06.1 score or with an
Artificial Analysis MATH-500 number.

## Differences from liquid_evals' math500

- **Repeats.** A liquid_evals run completes each problem once, and the model
  card reports the mean of 5 runs. Here the 5 runs are the 5 repeats of one
  cell, and pass@1 over the 2500 attempts equals the mean of the 5 per-pass
  scores.
- **Sampling.** By default, liquid_evals samples at temperature 0.6 with top_p
  1.0 and top_k -1 (off). The entry pins no top_p, top_k or min_p, so a client sends
  the temperature alone and the runtime's own defaults apply; llama.cpp's
  include `top_k = 40`.
- **Repetition stop.** liquid_evals stops a sample once a 2 to 128 token
  pattern repeats 10 times. A cell does that only on vLLM, with the
  [`repetition_detection`](https://github.com/Liquid4All/pipette-clients/blob/main/docs/methodology/evals.md#repetition-stop-repetition_detection)
  runtime flag set; otherwise such a sample runs to the context bound.
- **Reasoning markup.** liquid_evals strips only `<think>`, `[THINK]` and
  gpt-oss channels. The scorer also reads the reasoning and answer markup of
  Gemma 4, Cohere North, ERNIE and K2 Horizon. A completion without such markup is graded the same
  on both sides.
- **Dataset pin.** liquid_evals reads MATH-500 from the Hub without a revision
  pin. This set is pinned to one revision and checked by content hash.
